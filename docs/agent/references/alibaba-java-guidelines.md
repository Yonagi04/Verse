## 推荐和参考的使用方式

推荐/参考条款用于设计和审查启发，不默认阻断交付。满足以下任一情况时读取相应原文章节：

| 任务 | 重点章节 | 典型建议 |
| --- | --- | --- |
| 命名、重构、公共模型 | 编程规约：命名/OOP/注释 | 自解释命名、能力接口、不可变值对象、注释维护 |
| 集合、并发、性能代码 | 集合/并发/控制语句 | 初始化容量、减少共享状态、锁粒度、提前退出 |
| API、异常和日志 | 前后端规约/异常日志 | 错误分层、参数化日志、日志级别和上下文 |
| Service 单测 | 单元测试 | BCDE 原则、边界/正确/设计/错误场景、测试可维护性 |
| 表和查询设计 | MySQL 全章 | 字段类型、索引选择性、覆盖索引、批量操作、SQL 可读性 |
| Maven 和工程边界 | 工程结构 | 分层、依赖收敛、版本兼容和部署配置 |
| L2/L3 方案 | 设计规约 | 状态、时序、类关系、活动流、弱依赖与降级 |

## 采用原则

- 推荐项与 Verse 现有可靠约定一致时直接采用。
- 推荐项能缓解 `../quality-risk-controls.md` 中的已识别风险时，在技术方案中升级为本次任务约束。
- 参考项只在确有场景时使用，不得为了“遵守手册”引入额外层、模式、缓存或中间件。
- 手册基于 2022 年生态。Java 21、Spring Boot 3、MyBatis-Plus 或现代安全实践已有更合适做法时，保留条款目标，采用当前技术实现，并记录依据。
- 不以“手册没有要求”为由忽略业务语义、一致性、租户隔离、幂等、可观察性等 Verse 更严格的约束。

## 自动化边界

Alibaba P3C-PMD 只覆盖手册的一部分规则。静态检查适合发现命名、集合、并发和部分 API 误用，不能证明业务状态、表职责、索引有效性、事务一致性或测试断言质量。

在 P3C/PMD 尚未接入当前 Maven 构建前，Agent 必须执行人工 Gate，不能声称“编译通过即符合手册”。后续若接入，应先建立存量违规基线，只阻断新增违规，并把工具误报/项目适配配置纳入版本控制。
