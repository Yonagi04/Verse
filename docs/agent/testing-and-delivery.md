# 测试与交付规范

## 测试选择

测试验证可观察行为，而不是私有实现细节：

- 纯业务规则、转换、路由和错误映射：快速单元测试。
- Service 编排：隔离外部依赖，覆盖正常、拒绝、空结果和依赖失败。
- Controller 契约、校验、鉴权和响应结构：MockMvc/Spring MVC 测试。
- Mapper、SQL、事务、锁、唯一约束和 Outbox：数据库集成测试。
- 缓存：命中、未命中、隔离、失效、事务栅栏、Redis 降级和并发热点测试。
- Provider Adapter：固定请求/响应 fixture，覆盖协议差异、错误、流式结束和取消。

Bug 修复应先增加能复现问题的回归测试，再修复实现。若无法合理自动测试，必须说明原因和替代验证。

## 最低场景

新增或修改业务逻辑至少评估：

- 正常路径；
- 非法输入或业务拒绝；
- not-found/空结果；
- 边界值和分页边界；
- 无权访问和跨租户访问；
- 数据库、缓存、消息或 Provider 失败；
- 重试、重复请求和并发竞态；
- 旧调用方和历史数据兼容。

不是每项都必须生成一个测试，但省略与需求相关的场景必须有合理依据。

## 执行顺序

1. 开发过程中反复运行最小相关测试：`mvn test -Dtest=ClassName`。
2. 修改完成运行所有受影响测试类和 `mvn compile -q`。
3. 以下情况运行 `mvn test`：公共组件、配置、AOP、权限、事务、缓存、数据库 migration、异步/Outbox、Provider 注册或跨模块重构。
4. 交付制品或依赖/构建修改运行 `mvn clean package`。

不得把 `mvn clean package -DskipTests` 当成功验证；它只验证可跳过测试的构建路径。

## 失败处理闭环

测试失败时：

1. 保留失败命令、测试名和首个根因；
2. 单独重跑失败测试，排除套件噪声；
3. 将失败归类为本次回归、错误测试预期、非确定性、环境缺失或仓库既有问题；
4. 修复根因，不允许删除测试、降低断言、无条件延长 sleep 或吞掉异常；
5. 重跑失败测试，再重跑受影响集合；
6. 若修复改变设计或范围，更新计划和相应文档。

外部服务、凭据或基础设施缺失时，优先使用项目已有 fixture/Testcontainer/H2/Mock；不得伪造“测试通过”。

## 完成定义

交付前逐项确认：

- 实现满足需求且没有无关行为变化；
- API、权限、事务、缓存和错误语义已经检查；
- 新逻辑有与风险相称的测试；
- 相关测试与编译已经实际通过；
- 没有秘密、调试输出、临时开关或未解释 TODO；
- DTO/DO 字段中文说明、migration 和运维文档同步；
- 最终报告列出验证命令和结果，明确任何未验证项与风险。
