# Java 强制规约 Gate

本文件依据《阿里巴巴 Java 开发手册（黄山版）》v1.7.1（2022-02-03）整理，只承载“强制”级规则在 Verse 中的可执行基线。原手册由 Alibaba P3C 项目以 Apache-2.0 发布；原文和推荐/参考路由见 `references/alibaba-java-guidelines.md`。

本文件不是代码风格摘抄，而是 Harness Gate：任何适用项不满足，Production Gate 不通过。清单未展开的细节以原手册强制条款为准；与 Verse 明确冲突的条款只允许按文末适配表执行。

## 执行方法

1. 调研阶段标记本次变更涉及的章节，不得只检查最后修改的单个类。
2. 实施阶段对新增和修改代码持续检查；触及遗留违规时不得继续复制或扩大。
3. Production Gate 按适用章节逐项自检，并记录强制违规、修复或适配编号。
4. 能由编译器、格式化器、静态分析或测试证明的规则优先自动验证；其余提供代码、SQL、EXPLAIN、配置或评审证据。
5. 强制项偏离必须引用适配编号；无既有适配时先说明冲突、风险和替代控制并取得用户批准。

## 1. 命名、常量与格式

- 标识符使用有意义的英文，不使用中文、拼音混搭、侮辱性词汇、随意缩写，也不以下划线或美元符号开头/结尾。
- 类名 UpperCamelCase；方法、参数和变量 lowerCamelCase；常量全大写并以下划线分隔；包名全小写、单数语义。
- 抽象类使用 `Abstract` 或 `Base` 前缀，异常类以 `Exception` 结尾，测试类以被测类名开头并以 `Test` 结尾。
- POJO Boolean 属性不使用 `is` 前缀；数据库 `is_xxx` 字段必须显式映射。父子类成员和不同代码块变量避免同名遮蔽。
- 禁止未命名的业务魔法值；`long` 使用大写 `L`，浮点字面量使用大写 `D/F`。
- 使用 4 空格和 UTF-8，禁止 Tab；运算符、关键字、括号、逗号和注释空格保持统一；单行原则上不超过 120 字符。
- 数组声明使用 `Type[]`；所有 override 方法加 `@Override`；静态成员通过类名访问。
- 变量类型定义禁止使用 `var`，除非类型显然可推断。

## 2. OOP、数值与数据对象

- 不使用已废弃 API；公共契约签名不得静默破坏，废弃接口必须标注替代方案和迁移路径。
- equals 使用非空常量/确定值调用；包装整型使用 `equals`；重写 `equals` 必须同时重写 `hashCode`，作为 Set 元素或 Map Key 的自定义对象必须满足该契约。
- 金额使用最小货币单位的整型或经设计确认的 `BigDecimal`；禁止 `BigDecimal(double)`，比较使用 `compareTo`；浮点数禁止直接等值比较。
- DO 属性类型必须匹配数据库字段；DTO/DO 不设置掩盖“未提供”和“默认值”差异的隐式字段默认值。
- 构造器不执行业务逻辑或远程/持久化副作用；初始化行为使用清晰工厂或初始化方法。
- POJO 的字符串表示不得泄露密钥、Token、个人敏感信息或完整 Prompt；使用 Lombok 时同样检查生成行为。
- 同一属性不得同时暴露冲突的 `isXxx()` 与 `getXxx()`。

## 3. 日期、集合与控制流

- 日期时间使用 `java.time`；格式中严格区分 `y/Y`、`M/m`、`H/h`，不得硬编码一年 365 天。
- 集合判空使用 `isEmpty()`；不可修改集合、`Arrays.asList`、`subList` 和 Map 视图不得执行不支持的结构修改。
- `Collectors.toMap` 明确重复 Key 合并策略并处理 null value；集合转数组使用类型一致的 `toArray(T[]::new)` 或长度 0 数组。
- foreach 中不得直接增删集合；泛型上下界遵循 PECS，禁止把原始类型集合无检查赋给泛型集合。
- Comparator 满足自反、传递和对称契约。
- `if/for/while/do` 即使单行也使用大括号；switch 处理 fall-through、default 和外部 String 的 null。
- 高并发计数或退出条件不能依赖可能跳过的精确相等判断；自动拆箱前处理 null。
- 重复执行的正则表达式必须预编译为可复用的 `Pattern`，不得在热点循环中重复编译。
- 枚举字段必须私有且在构造后不可变，不得暴露修改枚举状态的 setter。
- 不使用 Apache `BeanUtils` 等依赖反射和字符串属性名的通用拷贝作为领域对象映射主路径；优先显式映射或项目既有、类型可检查的转换方式。
- 需要随机数时根据语义选择实现；并发场景不得共享存在竞争或瓶颈的可变随机数生成器，安全令牌不得使用普通伪随机数。

## 4. 并发与资源

- 单例及其方法必须线程安全；共享可变状态必须给出并发模型。
- 线程由受管线程池提供并使用有意义名称；禁止直接 `new Thread` 和无界 `Executors` 工厂，线程数、队列、拒绝策略和关闭行为必须显式。
- 优先使用 `java.time`，不得共享非线程安全格式化器；自定义 ThreadLocal 必须在 `finally` 清理。
- 锁粒度最小化；多资源加锁顺序一致；获取、持有判断和释放必须保证异常安全。
- 并发更新同一记录必须使用原子 SQL、唯一约束、乐观锁、悲观锁或经证明的分布式互斥，禁止读后写覆盖。
- 定时任务使用受管调度器，单任务异常不能终止全部调度；任务必须有界、可观测且支持安全重入。
- 流、连接和其他资源使用 try-with-resources 或等价的可靠关闭机制；`finally` 禁止 return。

## 5. 注释、API 与错误契约

- 公共契约、接口/抽象方法和非显然不变量使用有效 Javadoc，说明参数、返回、异常和业务语义；禁止生成复述代码的无效注释。
- 枚举值说明业务含义；DTO/DO 字段继续遵循中文说明要求。
- API 明确协议、路径、HTTP 方法、请求、状态、响应和错误契约；JSON Key 使用 lowerCamelCase。
- 列表无结果返回空集合，不返回 null；大整数跨 JavaScript 边界时使用字符串或明确的安全表示。
- URL/body、分页和文件上传必须设置并校验大小/范围上限；路径和字段兼容按 API 规范执行。
- 错误码用于稳定定位，不能随意新增、复用或直接作为用户文案；内部原因、可安全展示文案和 HTTP 语义分离。

## 6. 异常与日志

- 可预检查的参数/边界问题不以捕获运行时异常代替校验；异常不得充当正常流程控制。
- catch 必须按可恢复语义分类并真正处理、转换或继续抛出；禁止吞异常、只打印后返回成功或无条件重试。
- 捕获和抛出类型必须匹配；事务异常被捕获后仍需确保回滚语义。不得 blanket catch `Throwable` 吞掉 JVM Error，适配见 A-06。
- 使用 SLF4J 门面和参数化日志；禁止 `System.out/err`、`printStackTrace`、字符串拼接和无界对象 JSON 序列化。
- 异常日志包含必要上下文和堆栈，但必须脱敏；同一异常只在有责任处理的边界记录，避免层层重复。
- 日志级别、保留、审计期限和备份由环境配置并满足合规要求；代码不得假定本地文件策略等于生产策略。

## 7. 单元测试与安全

- 单元测试遵循 AIR：自动、独立、可重复，必须有能发现错误实现的断言，禁止人工观察输出。
- 测试不依赖执行顺序或真实不稳定外部环境；核心增量业务必须通过相关测试。新增测试范围仍受根 `AGENTS.md` 的治理边界约束。
- 用户资源必须在权威边界执行权限与所有权校验；跨租户隔离同时落实到 Service、SQL 和缓存 Key。
- 所有外部输入执行类型、范围、长度、枚举和业务合法性校验；SQL 使用参数绑定，禁止输入拼接和 `${}`。
- 敏感数据展示、日志和错误响应必须脱敏；HTML 输出转义，外部重定向使用白名单，状态变更请求具备适用的 CSRF/重放防护。
- 短信、邮件、支付等有成本能力必须有认证、幂等、频率和总量限制；上传校验大小、类型、内容和存储边界。
- 密钥不得明文提交仓库，使用环境/密钥服务管理并支持轮换。

## 8. MySQL、索引、SQL 与 ORM

- 表和字段小写 snake_case，不使用保留字；命名表达单一职责。金额/精度数据使用 decimal 或最小单位整数，禁止 float/double。
- 表字段和生命周期规则在设计中明确；主键、审计时间、逻辑/物理删除按 A-08 适配，不能机械加字段。
- 业务唯一性必须由唯一索引保证；索引必须来自真实查询的过滤、连接、排序和基数，不能凭字段猜测。
- 多表连接字段类型一致并有适当索引；复杂连接必须评审和 EXPLAIN。左/全模糊搜索不得直接拖垮主库。
- 计数使用正确的 `count(*)`/distinct/null 语义；聚合可能返回 null 时显式处理；分页 count 为 0 时不执行无意义数据查询。
- 禁止存储过程承担业务逻辑；数据订正先查询、限定范围、备份/审计并提供恢复方案。
- 查询明确字段，禁止 `SELECT *`；多表字段带别名；禁止 SQL 字符串拼接和不受控 `${}`。
- ORM 返回稳定 DTO/Projection，不用裸 HashMap 逃避契约；更新路径维护审计字段和并发控制。
- Schema/Migration 必须评审表职责、约束、索引、历史数据兼容、锁表风险、前滚和回滚/恢复。

## 9. 依赖、远程调用与设计

- Maven 坐标和版本遵循语义版本；生产不依赖 SNAPSHOT；相同依赖不得出现冲突版本。
- 新增/升级依赖必须检查依赖树、传递变化、许可证、安全和运行兼容，不能只验证直接功能。
- 所有远程调用设置连接、响应/读取和整体超时；同时定义可重试错误、最大次数、退避、幂等、降级和取消。
- 存储方案与底层数据结构必须评审并文档化。状态超过 3 个、复杂多方调用或模型关系时，技术方案使用状态表/图、时序和关系视图表达，不以 prose 模糊带过。
- 弱依赖必须识别故障影响，提供降级、隔离、恢复和应急预案；不得把外部系统成功当作本地事务的隐含前提。

## Verse 适配表

| ID | 手册强制条款 | Verse 适配 | 理由与替代控制 |
| --- | --- | --- | --- |
| A-01 | 所有 Service/DAO 必须接口化并以 Impl 区分 | Mapper/外部 Port 保持接口；公开且存在替换边界的 Service 沿用接口。单实现的内部策略、Policy、Helper、Job 不为形式强制一一接口 | KISS/YAGNI；依赖倒置施加在易变边界而非类数量 |
| A-02 | 所有类写创建者和创建日期 | 不写作者/日期标签 | Git 历史是权威来源，避免过期归属；类级 Javadoc 说明职责和约束 |
| A-03 | 类、属性、方法全部 Javadoc | 公共契约、接口、抽象方法、非显然不变量必须 Javadoc；普通私有实现不写复述式注释 | 提升信噪比；DTO/DO 字段中文说明继续强制 |
| A-04 | POJO 全部使用包装类型、无默认值并手写 toString | 边界 DTO/DO 使用可表达缺失的类型且无隐式默认；领域内部在“不存在缺失语义”时可用 primitive；Lombok 生成可接受但敏感字段必须排除 | Java 21 和项目 Lombok 约定；防止空值滥用与敏感泄露 |
| A-05 | 固定五位错误码和特定成功码 | 沿用 `IErrorCode`、`BaseErrorCode` 和领域错误码体系 | 保持既有 API 契约；仍强制唯一、稳定、可追踪和用户文案分离 |
| A-06 | RPC/动态调用 catch Throwable | 只在最外层隔离边界捕获 Throwable 且必须重新抛出致命 Error；业务代码捕获明确异常 | 防止吞掉 OOM、StackOverflow 等不可恢复错误 |
| A-07 | 越界分页返回最后一页 | 按 Verse API 契约校验或返回空页，不静默改写用户请求 | 隐式跳页会掩盖调用方错误，分页语义由 API 统一定义 |
| A-08 | 所有表必须 id/create_time/update_time 且一律逻辑删除、无外键 | 依据数据生命周期决定；业务主表优先继承 `BaseDO`，不可变事实/关联/Outbox 可例外；逻辑或物理删除、外键与否必须在数据设计中说明 | 避免无意义字段和无限积累；用唯一约束、审计、清理策略和应用不变量替代机械规则 |
| A-09 | 超过三表禁止 JOIN、varchar 索引必须前缀 | 复杂 JOIN 默认阻断，只有查询与索引设计评审、EXPLAIN 和数据量证据通过后例外；前缀索引根据版本、排序规则和选择性决定 | 以实际执行计划而非固定数字证明性能 |
| A-10 | 每张表必须 XML resultMap、禁止 resultClass | MyBatis-Plus 单表映射可用注解/约定；自定义 SQL、多表 Projection 和字段不一致时显式映射与别名 | 适配 MyBatis-Plus 3；仍禁止模糊映射与裸 Map |
| A-11 | 日志文件名和固定保存期限 | 代码遵守结构化、脱敏和级别规则；保存、备份、审计期限由部署与合规配置验证 | 应用代码不控制平台日志生命周期 |
| A-12 | 图的固定数量阈值 | L2/L3 达到复杂度阈值时必须提供等价的状态表/图、时序、数据关系或活动流；简单 L1 不制造形式化图 | 保留“消除歧义”的目的，允许 Markdown/Mermaid/表格等可维护表达 |
| A-13 | 固定的前后端错误响应字段 | 以现有 `Result<T>`、`IErrorCode` 和全局异常处理契约为权威；新增错误同时满足机器可判定、日志可定位和用户提示可理解 | 保持已发布契约，同时保留错误分层和可观测性目标 |
| A-14 | Velocity、JSP 等专项规则 | 项目未使用时不适用；一旦引入，必须在方案中补充输出转义、上下文隔离和模板安全规则 | 不为不存在的技术制造约束，但不能漏掉引入后的安全边界 |
| A-15 | SQL 空值判断使用特定函数写法 | 优先使用标准 `IS NULL` / `IS NOT NULL`；仅在确需函数返回值语义时使用 `ISNULL()` | 保留 null 语义正确性，同时提高 SQL 可读性和可移植性 |

适配表不是弱化入口。新增适配必须修改本文并在 L2/L3 评审中说明，不能在任务最终说明里临时宣称“本项目例外”。
